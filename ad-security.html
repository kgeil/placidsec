Active Directory Security

Executive Summary

Ten Priorities for Active Directory

Most Active Directory takeovers follow the same path: capture or relay a password on the internal network, reuse it to move from machine to machine, and climb to Domain Admin. These ten controls break that chain.

I drew them from the Center for Internet Security (CIS) benchmarks for Windows Server 2019, 2022 and 2025, and ranked them by how much real-world compromise each one prevents. They are written for the domains I see most often, with Windows Server 2019 domain controllers.

  1. Separate and restrict privileged accounts

    Keep Domain Admins to a handful of people, give them separate admin accounts, and let those accounts sign in only to domain controllers and dedicated admin machines.

  2. Deploy Windows LAPS and block local admin reuse

    Give every computer its own random local administrator password, rotated automatically, so one stolen password does not unlock the whole network.

  3. Remove broadcast name resolution

    Turn off LLMNR, NetBIOS name service, mDNS and WPAD. Attackers on the network use them to trick computers into handing over passwords.

  4. Require SMB signing; remove SMBv1

    Make file-sharing connections prove they are genuine, which stops stolen logins being replayed to other servers, and remove the obsolete SMBv1 protocol.

  5. Require LDAP signing and channel binding

    Stop attackers relaying stolen logins to the domain controllers to change Active Directory itself.

  6. Use managed service accounts; harden the rest

    Let Windows manage service account passwords automatically. Where that is not possible, use long random passwords and minimal rights.

  7. Strong password and lockout policy

    Require at least 14 characters, longer for admin and service accounts, and lock accounts after repeated failed guesses.

  8. Retire LM and NTLMv1; restrict NTLM

    Refuse old login methods whose passwords can be cracked in minutes, and track what still uses NTLM so it can be phased out.

  9. Harden the domain controllers

    Turn off services domain controllers do not need, such as printing, and protect the passwords held in their memory.

  10. Audit domain controllers and keep the logs

    Record who signed in, what changed and who was given admin rights, keep it off the server, and alert on high-risk events.

Where to Start

Items 1 to 3 Come First

The first three close the paths attackers use most often inside a network, and items 2 and 3 are among the quickest wins available.

Everything on this list works with Windows Server 2019 and needs no extra licensing. Windows Server 2025 turns several of these protections on by default, so doing them now also smooths a future upgrade.
